# Исходники документа pandocster

Эти правила действуют на Markdown, из которого `pandocster` собирает один
документ. Перед правкой или созданием `.md` загрузи скилл
`pandocster-markdown`: в нём примеры и краевые случаи. Не выдумывай синтаксис,
которого нет ниже и в скилле.

## Куда писать

- Текст — в `.md` под `src/`. Картинки — рядом с файлом или в `src/assets/`.
- `src/templates/` сборка не читает. Текст туда не клади.
- Не меняй исходники обходным путём через `build/`. Сборка копирует дерево и
  работает с копией.
- Не пиши вручную `<!-- @header-offset: N -->`, `<!-- @anchor="..." -->` и
  `999-reflinks.md`. Первые два сборка дописывает сама, третий собирает сама.

## Структура

Корень структуры — каталог сборки, если в нём уже есть `.md`. Иначе это
родитель первого каталога, где `.md` нашёлся. Для обычного каркаса корень —
`src/md`: положи туда разделы.

- В каждом каталоге раздела может лежать `_index.md`. Это заголовок раздела.
  Соседние `.md` подчинены ему.
- Верхний заголовок любого файла — всегда `#`. Глубину не считай и не пиши:
  сдвиг делает сборка. `#` в корневом `_index.md` станет H1, `#` в `_index.md`
  вложенного раздела — H2, `#` в соседнем файле — H3. Следующие заголовки файла
  пиши относительно его собственного `#`: `##`, `###`.
- В каталоге сначала идёт `_index.md`, потом остальные `.md` по имени.
  Вложенный каталог встаёт на место по своему имени. Для порядка ставь префикс
  `01-`, `02-`.
- В `_index.md` обычно только заголовок. Дополнительный текст допустим, но его
  заголовки окажутся на уровень выше, чем `#` соседних файлов.

## Ссылки, картинки, переменные

- Перекрёстная ссылка — reference-style, определение на всю строку, цель —
  относительный путь к `.md` внутри корня структуры:

  ```markdown
  См. [введение][intro].

  [intro]: ./01-intro.md
  ```

  Обычная ссылка `[текст](01-intro.md)` якорем не станет. Метка уникальна на
  весь документ. Одна метка на разные файлы даёт предупреждение, сборка не
  падает.
- Картинка — inline, путь от текущего файла: `![Схема](../assets/scheme.png)`.
  Адреса `http`, `https`, `ftp`, `mailto`, `data:` и `#` не копируются.
- Переменная объявляется в `pandocster.yaml` в `pandocster.variables`. В тексте
  `{{имя}}` и `{{ имя }}` — одно и то же. Имя — буквы, цифры и `_`. Неизвестное
  имя останавливает сборку. `\{{имя}}` остаётся буквально. В инлайн-коде и
  fenced-блоках замены нет.
- Перед новым именем прочитай `pandocster.yaml`. Если имени нет, добавь ключ
  только в `pandocster.variables` или `pandocster.numerators`. Остальной конфиг
  не переписывай.

## Нумераторы, диаграммы, страницы

- `{{имя}}` без решётки — переменная. Нумератор всегда начинается с `#`.
  Плоский номер: `{{#:para}}` или `{{#:para:item}}`. Иерархический: `{{##:h}}`.
  Ссылка на уже созданный номер: `{{#=:para:item}}`. Она счётчик не двигает.
  Безымянный `{{#}}` — нумератор `default`.
- Одно имя нельзя писать и с одной решёткой, и с двумя. Повторный генератор с
  тем же значением и ссылка без генератора останавливают сборку. Имя без записи
  в `pandocster.numerators` работает с настройками по умолчанию.
- Диаграмма — отдельный fenced-блок. Строка открытия ровно ` ```mermaid `,
  ` ```graphviz ` или ` ```graphiz `, без отступа и без хвоста. Закрытие ровно
  ` ``` `.
- Разрыв страницы — отдельная строка `<!-- @new-page -->`. Не ставь её перед
  каждым разделом: заголовок, ставший после сдвига H1, и так начинается с новой
  страницы.

## Сборка

Из корня проекта: `pandocster check`, затем `pandocster build src/ --to docx`
или `./generate.sh`. Результат — файл в текущем каталоге. Имя без флага берётся
из имени каталога; другое имя задаёт `--file-name`.
