# Нумераторы

Нумератор — это маркер в исходном Markdown, который при сборке заменяется
порядковым номером. Номера сквозные: один нумератор продолжается из файла
в файл в том порядке, в каком файлы потом попадут в документ.

Маркер всегда начинается с решётки. `{{имя}}` без неё — это переменная,
а не нумератор, и обрабатывается по правилам переменных. Знак `=` сразу
после решёток отличает ссылку от генератора: `{{#:item}}` создаёт номер,
а `{{#=:para:item}}` только подставляет уже созданный.

```markdown
{{#:para}} Первый абзац
{{#:para}} Второй абзац
{{#}} Абзац другого нумератора
{{#:para}} Третий абзац
{{#}} Ещё один абзац другого нумератора
```

После сборки:

```markdown
1. Первый абзац
2. Второй абзац
1. Абзац другого нумератора
3. Третий абзац
2. Ещё один абзац другого нумератора
```

Исходники не меняются. Замена выполняется в подготовленной копии, в том же
проходе, что и подстановка переменных: до ссылок, картинок и диаграмм.

## Как записать маркер

Полная форма — `{{#:имя:значение}}`.

- Одна решётка задаёт плоский номер, две — иерархический.
- Имени может не быть. `{{#}}` и `{{#::значение}}` относятся к нумератору
  `default`.
- Имени значения может не быть. `{{#:para}}` и `{{#:para:}}` каждый раз
  получают новый номер, сослаться на него нельзя.
- Вокруг решётки, имени и значения допустимы пробелы:
  `{{ #: para : item }}` и `{{#:para:item}}` — один и тот же маркер.

Имя нумератора и имя значения состоят из букв, цифр и знака `_`. Дефис
маркер не принимает: `{{#:para:foo-bar}}` останется в тексте как есть.
Имя нумератора и имя переменной друг другу не мешают. `{{para}}` ищет
переменную `para`, а `{{#:para}}` считает нумератор `para`.

Обратный слэш перед маркером оставляет его буквально: `\{{#:para}}`.
Внутри кода на строке и внутри ограждения, включая блоки mermaid и graphviz,
маркер не считается и не заменяется. Значение переменной повторно не
разбирается: если `{{token}}` раскрылся в текст `{{#:para}}`, номер из этого
текста не появится.

Сломанная запись, например незакрытый `{{#`, тоже остаётся текстом.
Сборка из-за неё не останавливается.

## Генератор и ссылка

Имя значения само по себе ничего не запоминает. Номер создаёт только
генератор, а ссылка только подставляет его. У ссылки после решёток стоит `=`,
имя значения обязательно.

```markdown
{{#:para}} Первый абзац
См. пункт {{#=:para:item}} ниже.
{{#:para:item}} Абзац, на который нужна ссылка
{{#::note}} Абзац нумератора default
{{#:para}} Третий абзац
{{#}} См. {{#=::note}} и повтор {{#=:para:item}}
```

После сборки:

```markdown
1. Первый абзац
См. пункт 2. ниже.
2. Абзац, на который нужна ссылка
1. Абзац нумератора default
3. Третий абзац
2. См. 1. и повтор 2.
```

Сборка идёт в два прохода. Сначала по всему дереву создаются номера, и только
потом заменяются ссылки. Поэтому ссылка в раннем файле видит генератор
в позднем: порядок файлов больше не решает, где номер создаётся.

Ссылка получает готовую строку генератора: с префиксом родителя, разделителем
уровней и суффиксом. Заново номер не собирается. Несколько ссылок могут
указывать на один генератор. Одинаковые имена значений у разных нумераторов —
разные номера. Пара, которую помнит сборка, — имя нумератора и имя значения.

Второй генератор с тем же именем значения останавливает сборку. Ссылка без
генератора тоже останавливает сборку. В сообщении будут имя нумератора, имя
значения, файл и номер строки.

Ссылка не двигает счётчик и не открывает иерархический раздел, даже если
стоит в заголовке. В коде, ограждении и после обратного слэша она остаётся
текстом, как генератор. `{{#=:para}}` и `{{#=:para:}}` ссылками не считаются:
у них нет имени значения.

## Иерархический номер

Иерархический маркер пишется с двумя решётками: `{{##:h}}`. Новый номер
в заголовке получает префикс ближайшего предыдущего заголовка с маркером
того же нумератора. Маркер вне заголовка добавляет ещё один компонент
к этому родителю.

```markdown
# {{##:h}} Введение

## {{##:h}} Условия

{{##:h}} Первый пункт

{{##:h}} Второй пункт

## {{##:h}} Порядок

{{##:h}} Первый шаг

{{##:h}} Второй шаг
```

После сборки:

```markdown
# 1. Введение

## 1.1. Условия

1.1.1. Первый пункт

1.1.2. Второй пункт

## 1.2. Порядок

1.2.1. Первый шаг

1.2.2. Второй шаг
```

Родителем становится только маркер в заголовке. Два маркера подряд в обычном
тексте — соседи, а не родитель и ребёнок. Заголовок без маркера иерархию
не меняет: следующий номер по-прежнему считается от последнего заголовка,
где маркер был.

Глубина номера совпадает с визуальным уровнем заголовка в собранном
документе. Этот уровень уже учитывает сдвиг `@header-offset`, поэтому
заголовок в `_index.md` и заголовок в соседнем файле получают такую глубину,
на которой их увидит читатель. Если между родителем и новым заголовком
уровень пропущен, недостающие компоненты заполняются единицей. После номера
`1.` заголовок третьего уровня получит `1.1.1.`.

Пока иерархического родителя не было, маркер вне заголовка выдаёт один
компонент, как плоский номер: `1.`, `2.`, `3.`. Этот ряд отдельный и корневой
заголовок не сдвигает. Первый заголовок с маркером тоже получает один
корневой компонент и начинается со своего `start`.

Номера заголовков и текста на одной глубине берут один счётчик. Если после
заголовка `1.` обычный абзац получил `1.1.`, следующий заголовок той же
глубины получит `1.2.`.

В одном заголовке может стоять несколько иерархических маркеров одного
имени. Раздел открывает только первый: он получает номер. Остальные такие
маркеры в этой строке заменяются пустой строкой. Маркеры других нумераторов
в том же заголовке считаются отдельно. Ссылка в заголовке тоже не открывает
раздел и не получает новый номер.

Заголовком считается и ATX-запись `# Текст`, и setext-запись с подчёркиванием
из `=` или `-`. Заголовок внутри цитаты, списка, таблицы или другого
вложенного блока — обычный текст. Он номер получает, но родителем для
следующих номеров не становится.

Одно имя нельзя использовать сразу в обеих формах. Если `{{#:h}}` уже
встречался, `{{##:h}}` останавливает сборку. В сообщении будут имя, файл
и номер строки.

## Порядок файлов

Номер зависит от порядка сборки, а не от алфавитного обхода каталога.

В каждом каталоге сначала обрабатывается `_index.md`, затем остальные `.md`
по имени. Вложенный каталог идёт на своём месте по имени, и его `_index.md`
тоже раньше соседних файлов. Поэтому маркер в `_index.md` получает номер
раньше маркера в файле рядом, даже если имя `_index.md` стоит в алфавите
позже.

Файл `999-reflinks.md` в нумерации не участвует. Это служебный файл
перекрёстных ссылок, и маркеры в нём не заменяются.

## Настройки

Узел `pandocster.numerators` необязателен. Ключ — имя нумератора. Имя,
которого в конфиге нет, тоже работает: для него действуют значения по
умолчанию. Пустой узел и `null` означают то же самое. Если узел не словарь,
сборка останавливается.

```yaml
pandocster:
  numerators:
    para:
      suffix: ". "
      start: 1
    h:
      delimiter: "."
      start: 1
```

У нумератора три поля.

- `suffix` — строка после номера. По умолчанию это точка, поэтому
  `{{#:para}} Текст` превращается в `1. Текст`. Пробел после номера в этом
  примере берётся из исходной строки. `suffix: null` и пустая строка не
  добавляют ничего. Значение вроде `". "` добавляет и точку, и пробел уже
  само.
- `start` — целое число, с которого начинается нумератор. По умолчанию 1.
  Для иерархического нумератора оно задаёт только корневой компонент.
  Вложенные компоненты всегда начинаются с 1.
- `delimiter` — строка между компонентами иерархического номера.
  По умолчанию точка, поэтому получается `1.1.2.`. У плоского нумератора
  поле ни на что не влияет.

Неизвестное поле внутри настроек нумератора пропускается. Неверная строка
имени, нестроковый `suffix`, нецелый `start` или нестроковый `delimiter`
останавливают сборку.
