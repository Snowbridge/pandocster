# AGENTS.md

Инструкции для агентов, которые меняют этот репозиторий.
Пользовательский обзор — в [README.md](README.md). Этот файл описывает,
как устроен код и какие правила нельзя нарушать.

## Что это

`pandocster` (версия в [pyproject.toml](pyproject.toml)) — CLI вокруг
[pandoc](https://pandoc.org/). Python готовит дерево Markdown к вёрстке,
вёрстку делает pandoc.

Точка входа: `pandocster = cli.entrypoint:main`.
Python ≥ 3.10. Зависимости: `click`, `pyyaml`.
Внешние инструменты: pandoc ≥ 3.8.3 с Lua ≥ 5.4; для диаграмм опционально
`mmdc` ≥ 11.12.0 и Graphviz `dot` ≥ 14.1.1.

## Язык

Отвечай пользователю по-русски, пока он явно не попросит другой язык.
Идентификаторы, команды, пути и сообщения CLI оставляй как в коде.
Комментарии в существующем коде не переписывай «для единообразия».

## Слои

CLI и бизнес-логика разделены. Не клади логику в обработчики Click.

| Слой | Где | Ответственность |
| --- | --- | --- |
| CLI | `src/cli/<command>.py` | аргументы, опции, `echo`, `SystemExit` |
| Команды | `src/service/commands/<command>.py` | подготовка дерева, вызов pandoc, ошибки |
| Конфиг | `src/config/` | схема (`schema.py`) и разбор YAML (`load.py`) |
| Общее | `src/service/` | обход `.md`, subprocess, лог `--log` |
| Фильтры | `src/pandoc-filters/*.lua` | сдвиг заголовков, якоря, разрывы страниц |

Новая команда — два файла с одним смыслом имени:
`src/cli/<name>.py` и `src/service/commands/<name>.py`.
CLI-модуль импортируется из `src/cli/entrypoint.py`, иначе команда не
зарегистрируется. `prepare` скрыта (`hidden=True`); не показывай её в
`--help`, если задача этого не требует.

Пакет `src/pandocster/` почти пустой. Рабочий код живёт в `cli`, `config`,
`service` и `pandoc-filters`, которые setuptools находит из `src/`.
Не переноси их под `pandocster` без отдельной задачи на смену импортов и
`[project.scripts]`.

## Конвейер сборки

`build` вызывает `run_prepare`, затем pandoc. Флаг `--prepared` пропускает
подготовку и считает `src` уже готовым каталогом сборки.

`run_prepare` делает строго это:

1. Проверяет, что `src` и `build` существуют как каталоги и не пересекаются.
2. Очищает `build` и копирует туда `src`. Исходники не изменяются.
3. Находит `ROOT_LEVEL`: сам `build`, если в нём есть `.md`, иначе родителя
   первого каталога с `.md`.
4. В начало каждого `.md` пишет две строки:
   `<!-- @header-offset: N -->` и `<!-- @anchor="..." -->`.
   Якорь — относительный путь от `ROOT_LEVEL`, части склеены `_`.
   Для `_index.md` уровень равен глубине каталога (`current_level`).
   Для остальных файлов уровень на 1 больше. Глубина: файл в корне = 1,
   каждый вложенный каталог добавляет 1.
5. В каждой исходной строке заменяет `{{name}}` значениями из
   `pandocster.variables`, если узел задан. `{{ name }}` — то же имя.
   `\{{name}}` остаётся буквально `\{{name}}`. Инлайн-код и fenced-блоки,
   включая mermaid и graphviz, не меняются. Неизвестное имя — `PrepareError`
   с именем, путём и номером строки. Скаляр вставляется текстом
   (`true`/`false` в нижнем регистре, `null` — пустая строка); список и
   словарь — фрагментом YAML. Значение повторно не сканируется.
6. Локальные картинки копирует в `build/resources/`, сохраняя путь относительно
   корня проекта сборки, и переписывает `![](...)`. URL, `mailto`, `data:` и
   `#` не трогает. Файл вне дерева сборки или отсутствующий файл оставляет
   как есть и печатает предупреждение.
7. Reference-style ссылки на `.md` внутри `ROOT_LEVEL` вырезает из исходных
   файлов и собирает в `999-reflinks.md` как `[label]: #anchor`.
   Неоднозначные метки — предупреждение, не ошибка.
8. Ограждения ` ```mermaid ` и ` ```graphviz ` / ` ```graphiz ` заменяет на
   картинку, если соответствующий инструмент включён в конфиге.
   Иначе блок остаётся текстом.

`run_build` собирает `.md` под каталогом сборки: в каждом каталоге сначала
`_index.md`, затем остальные по имени. Вызывает pandoc с
`--resource-path=resources`, опциями и metadata из конфига и Lua-фильтрами.
Результат — `<file-name>.<format>` в текущем каталоге; без `--file-name` имя
берётся из имени cwd. Каталог сборки удаляется, если не передан
`--preserve-build`.

Порядок фильтров по умолчанию фиксирован:

1. `header_offset.lua` — сдвиг заголовков по `@header-offset`.
2. `link_anchors.lua` — `@anchor` в id / `\label` / HTML span.
3. `absorb_nonvisual_paragraphs.lua` — пустые абзацы с якорем сливаются со
   следующим блоком.
4. `newpage.lua` — разрыв страницы перед заголовком уровня 1 и по
   `<!-- @new-page -->`.

Фильтры читаются через `importlib.resources` пакета `pandoc-filters`.
Новый фильтр нужно добавить и в каталог, и в `_DEFAULT_FILTER_ORDER` в
`src/config/schema.py`.

## Конфиг

Корень YAML — ключ `pandocster`. Приоритет `load_config`:

1. `./pandocster.yaml`;
2. `~/.config/pandocster/config.yaml`;
3. встроенные значения `default_config()`.

Локальный `pandocster.yaml` в корне этого репозитория в `.gitignore`: это
конфиг документа, не исходник инструмента.

`variables` — необязательная мапа. Нет ключа, `null` или `{}` — подстановки
нет. Имя ключа после `strip`: буквы, цифры и `_`; иначе `ConfigError`.
Пустая мапа в `config show` и `init` не сериализуется.

Если в файле есть `pandoc`, но нет `filters`, фильтры **не** подставляются
из умолчаний — список пустой. `metadata` и `options` при отсутствии ключа
берутся из умолчаний. `metadata` — произвольный YAML: его не разбирают,
а пишут во временный файл и передают как `--metadata-file`.

Умолчания pandoc: `bin: pandoc`, `--toc`, `--toc-depth=3`, `--standalone`,
`--embed-resources`, metadata `lang: ru` и `toc-title: Оглавление`.

`diagrams.mmdc` и `diagrams.graphviz` включаются, только если проверка версии
прошла. В YAML у инструмента обязательны `enabled` и `bin`; `format` по
умолчанию `png`.

Ошибки конфига — `ConfigError`. Ошибки команд — `PrepareError`, `BuildError`,
`InitError`. CLI ловит их и завершается с кодом 1. Не пробрасывай сырой
traceback пользователю.

## Команды

| Команда | Назначение |
| --- | --- |
| `init [dir] [--force]` | `pandocster.yaml`, `src/md`, `src/assets`, `src/templates`, `generate.sh` |
| `check` | pandoc и Lua обязательны (код 1); `dot` и `mmdc` — предупреждение |
| `prepare <src> [build]` | только подготовка; скрытая команда |
| `build <src> [build] --to <format>` | подготовка и pandoc; форматы — список `_TO_CHOICES` |
| `config show` / `config create [--global] [--force]` | показать или записать эффективный конфиг |

Общий флаг `--log` скрыт. Он пишет в cwd файл `<UTC-timestamp>.log` через
`src/service/command_log.py`. Не делай его видимым в help без задачи.

Внешние процессы запускай только через `Runner` из
`src/service/subprocess_runner.py`. На Windows `shell=True`, потому что
`mmdc` ставится как `.cmd`, а вывод читается в OEM-кодировке консоли
(`cp866` на русской Windows), не в UTF-8. В тестах подменяй runner,
не вызывай pandoc, `dot` и `mmdc` по-настоящему.

## Документ-пример

`docs/` — исходники, которые сама утилита умеет собирать, а не документация
API. Правила дерева:

- каталог раздела может содержать `_index.md` — заголовок раздела;
- соседние `.md` подчинены этому `_index.md`;
- картинки лежат рядом или в `assets/` и ссылаются относительно файла;
- перекрёстные ссылки — reference-style на другой `.md`.

Не «улучшай» статьи в `docs/article/` попутно с правкой CLI.

## Как менять код

- Одна функция — одна ответственность. Повтор второй раз выноси в функцию,
  не копируй блок.
- Сигнатуры публичных функций типизируй. `from __future__ import annotations`
  уже принят в модулях.
- Длина строки — 88. Линтер — только Ruff (`E`, `F`, `I`). Не добавляй
  flake8, black, isort.
- Формат Markdown в репозитории — CommonMark, без нарушений markdownlint:
  пустая строка вокруг заголовков и списков, один завершающий перевод строки.
- Не ослабляй проверки версий pandoc и Lua и не меняй смысл `_index.md`,
  якорей и `999-reflinks.md` без теста, который фиксирует новое поведение.
- `init` не должен затирать непустой каталог без `--force`.
- `config create` не должен затирать существующий файл без `--force`.

## Проверки

Окружение: `.venv`. Установка: `pip install -e ".[dev]"`.

Перед завершением задачи, которая трогает Python:

```bash
ruff check src tests
ruff format --check src tests
mypy src
pytest
```

`pytest` уже включает `--strict-markers` и `--cov=src`
([pyproject.toml](pyproject.toml), секция `[tool.pytest.ini_options]`).
Тесты лежат в `tests/test_<область>.py`. Общие фикстуры — в
`tests/conftest.py` (`write_file`). Внешние CLI мокай через `Runner` или
`monkeypatch`.

Pre-commit (`.pre-commit-config.yaml`): `ruff`, `ruff-format`, `mypy`,
`check-added-large-files`, `end-of-file-fixer`, `trailing-whitespace`.

## Чего не делать

- Не коммить `.venv/`, `build/`, `dist/`, кэши, `.coverage`, локальный
  `pandocster.yaml`.
- Не вызывать pandoc из CLI-слоя напрямую.
- Не менять порядок фильтров и формат маркеров `@header-offset` / `@anchor`
  в одном месте: Python пишет маркеры, Lua их читает.
- Не переименовывай `999-reflinks.md`: сборка сортирует файлы по имени, и
  этот файл должен идти последним.
- Не добавляй зависимость без причины. Диаграммы остаются внешними CLI.
